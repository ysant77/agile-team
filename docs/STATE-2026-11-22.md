## 4. The scope event of 22 Nov

- The deploy of `main` 2a31b9c failed `forge lint`: `src/action-guard.js` calls
  `GET /rest/api/3/myself`, which needs the scope `read:jira-user`, and the manifest did not
  declare it. The call came in with the action guard of 19 Nov; the version on the site was
  older. Only the Rovo actions that create a ticket or run discovery use it.
- PR 59 added `read:jira-user` and a test (`test/manifest-scopes.test.js`). The deploy made a new
  major version (5.0.0).
- **The install upgrade did not stop for the owner's approval.** It was run from the CLI without
  a terminal, and the CLI applied the new scope without a prompt. The plan was that the owner
  approves the scope first. The owner then reviewed it and accepted the scope. The added scope is
  `read:jira-user` only; the other scopes and the egress (`api.github.com`) did not change.
- From now on an install upgrade runs only interactively, so the person who approves sees the
  prompt.
- Later: take the account id from the action context instead of `/myself`, and remove the scope
  (fewer scopes for the final submission).
