# Evidence benchmark: independent cases, set 3 (16 Nov 2026)

This is independent set 3. The author read only `CASES-2-INDEPENDENT.md` (for the format),
`RESULTS-2.md`, `RESULTS-2-ARM-D.md` and the term sections (2 to 5) of `CASES.md`. The author did
not read the bank source code, any branch, any file under `run/`, the app's code or any
prediction. No model was run.

Rules:

- After the freeze of this file, no case, truth label or correct outcome changes.
- A case that cannot be built is marked `void` with a dated reason in a later commit. It stays in
  the count of cases made.
- This file has no prediction column. The builder adds predictions in a different file, before
  scoring.
- The terms (truth, evidence state, outcomes, "repro") are those of `CASES.md`, sections 2 to 4.
  The rows below state the outcome explicitly. They decide over the table in section 3 of
  `CASES.md`.
- No case of this set is a copy of a set 1 or set 2 case. Each ticket, behaviour and test is new.

## Columns

- **Class:** `control`, `weak-test`, `ci-state`, `high-stake`, `coverage`, `base-state` or `new`
  (a class that set 2 does not have).
- **State:** four items in a fixed order.
  - `Domain`: how a high-stake domain is marked: `spec` (the domain field of the stored ticket
    spec), `label` (a Jira label only), or `neither`.
  - `CI`: the state of the required `CI` pull request workflow on the head commit.
  - `Cov`: changed-line coverage of the report for the head commit.
  - `Sign-off`: `not needed`, or `needed, none recorded`.
- "Base" is the base commit of the PR. "Head" is the last commit of the PR branch.
- "Fails by an assertion" means that the test body reaches the assertion of the AC and the
  assertion is false.
